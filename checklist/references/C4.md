# C4 · CWV(Core Web Vitals)(P1)

## 介绍

Google 排名信号之一,量三件事:LCP(加载,<2.5s)、INP(交互响应,<200ms)、CLS(布局稳定,<0.1)。
判定用 CrUX 真实用户 75 分位(field data),Lighthouse 跑分只是 lab 参考。**需上线 + 约 28 天真实流量才有数据**,此前 checker 记 N.A.。

## 实现指导

- **LCP**:收录页走缓存 / 预渲染(见 C15);hero 图 `fetchpriority="high"` + 预加载、压缩(WebP/AVIF);关键 CSS 内联
- **INP**:控制 JS 执行量,长任务拆分(`scheduler.yield` / 分帧);内容页与交互页分离,内容页少挂脚本
- **CLS**:图片写死宽高(见 C18);字体 `font-display: swap` + 预载;广告/嵌入位预留占位
- 交付前自压:Lighthouse / PageSpeed Insights(lab 数据,自查用);上线后看 CrUX(PageSpeed Insights 上方 field 区块即是)
- 验收只认 CrUX;新站前 28 天 checker 记 N.A.(reason=need-crux-data)
- **checker 前置(接 CrUX API,约 3 分钟)**——免费、不绑卡、150 次/分钟;数据公开
  (任何域名可查,无需站点所有权)。未填 key = N.A.(reason=need-crux-key):
  1. Google Cloud **任意项目**(新建或用现成的都行,与站点无绑定关系)
  2. 搜 **Chrome UX Report API** → **Enable**
  3. **Credentials → + CREATE CREDENTIALS → API key**
     (走 API 详情页的 "Create credentials" 向导也行:选 *Public data* → Next;
     那句 "This API doesn't require credentials" 指不需要 OAuth,key 仍要建)
  4. 建好后 **Edit API key** → *API restrictions* 勾 **Chrome UX Report API** → Save
     (Application restrictions 留 **None** — 脚本从本机跑,IP 不固定);最多 5 分钟生效
  5. **Show key** 复制 `AIza…` → 填 `tools/check/config.py` 的 `CRUX_API_KEY`
  6. 验证:`python3 tools/check/run.py --site <id> --page-sample 1 --max-pages 1`,
     C4 行出 LCP/INP/CLS 数值即通;显示 `need-crux-data` = key 没问题,该域名样本量不足
  - 别复用其他服务在用的 key(权限范围与用量统计混在一起);key 属机密,不进公开 repo
