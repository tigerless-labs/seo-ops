# C25 · 无 mixed content(P2)

## 介绍

HTTPS 页面里引用 `http://` 子资源(图片、脚本、样式、iframe)= mixed content。
浏览器的处理是分级的:

- **主动混合内容**(script / iframe / css / fetch)—— **直接拦截,不加载**。
  被拦的若是渲染逻辑或样式,页面对爬虫可能就是残页或裸 HTML
- **被动混合内容**(img / audio / video)—— 现代浏览器默认**自动升级到 https**;
  升级失败(对方不支持 https)则拦截,图片开天窗

对我们的直接影响:**爬虫看到的页面和你以为的不是同一个**。这与 C14(body-hide 脚本)、
C9(CSR 空壳)是同一类病——**页面在浏览器里看着没事,在抓取面上已经缺了**。
只是 mixed content 的破坏程度通常局部,故定 P2。

## 判定范围

只判**子资源**引用协议:`img` / `script` / `iframe` / `video` / `audio` / `source` /
`embed` / `object` 的 `src`,以及 `link` 的 `href`(样式表等)。

**`<a href="http://…">` 不算**——那是导航出链,用户点了才跳,不触发混合内容拦截,
不影响本页渲染。判它只会制造噪声。(出链的可达性归 C6。)

http 页面本身不判(无「混合」可言),记 N.A.。

## 实现指导

- 所有站内资源写**协议相对或绝对 https**;别在模板里硬编码 `http://`
- 第三方嵌入(统计、客服、地图、视频)接入前确认对方支持 https;
  不支持的**不接**——为一个不支持 https 的第三方牺牲整页渲染不划算
- CMS / content 供稿里粘贴的外部图片 URL 是常见来源:入库时统一改写协议,或直接转存自家 CDN
- 兜底(不是解法):`Content-Security-Policy: upgrade-insecure-requests`
  让浏览器自动升级——能救线上,但**掩盖问题**,checker 仍应扫源码判红
- 自查:抓页 grep `="http://`(排除 `<a`);浏览器控制台的 Mixed Content 警告
