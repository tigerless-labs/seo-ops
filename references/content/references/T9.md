# T9 · OG 分享文案 + 分享图指定(每页)

> 下游:[C19 OG 分享卡](../../checklist/references/C19.md) — 判标签齐全 + `og:image` 绝对 URL + 尺寸声明。

## 介绍

链接被贴进微信、X、Slack、飞书时弹出的那张预览卡,内容全部来自 `og:` 标签。
缺了,平台就自己乱抓 —— 通常抓到导航里第一张图(logo)和页头第一段字(cookie 提示)。

这条和 [T5 title/description](T5.md) 的区别是**场景不同**:

- title/desc → 搜索结果,读者在**主动找**,已经有意图
- OG → 社交流,读者在**刷**,你要在一秒内拦住他

所以文案默认可以同源,但差异化时值得单独写:搜索场景写清楚是什么,社交场景写勾住人。

## 怎么交

### 文案

默认同 title/description,不用重复交。需要差异化时单独写一行:

```yaml
og_title: 身份转换期断保,可能要自己扛几万美金
og_description: F1 转 H1B 中间那段 gap,三种情况的保险衔接方式,一张图讲清。
```

### 分享图

**缺省取正文主图**,不用交。只有主图不适合当卡片时才在这里指定:

```yaml
og_image: /og/f1-to-h1b-card.png     # 主图是图标/尺寸不对时指定
```

什么时候需要指定:

- 正文没有主图(纯文字页)
- 主图是图标、头像、装饰图(**tigerless.ai 现在踩的就是这个** —— og:image 是一张 512×512 的
  app icon,分享出去是个小方块)
- 主图很长(信息图、时间轴)—— 按 1200×630 裁会把内容切掉,需要单独做一张

规格:**1200×630 px**,绝对 URL,不被 robots 拦。

## 常见错误

- **分享图用 logo** —— 每条分享长得一模一样,读者划过去不会停
- **图里放小字** —— 卡片在手机上缩到很小,正文字号的字全糊掉;图上要放字就放大字,三五个词
- **用了带透明背景的 PNG** —— 不同平台补的底色不同,深色模式下可能变成一团黑
- **og_description 写得比 desc 还干** —— 社交场景是唯一可以写得有钩子的地方,浪费可惜
- **分享图和页面内容无关** —— 点进来发现货不对板,比没有图更伤

> `og:type`(文章页填 `article`)**不用交** —— 模板看本页有没有文章正文就能定,
> frontend 派生。同一个事实不重复供给。
