# T10 · date_modified upkeep (per page)

> Downstream: [C21 YMYL trust block](../../checklist/references/C21.md) — the human review judges "JSON-LD matches the visible page".

## Introduction

One date, two outlets:

- the visible "Updated 2026-08-25" on the page
- `dateModified` in the JSON-LD

**The two must share one source and one value.** A mismatch is a straight red in the C21 human
review — it means the page tells readers one thing and machines another, which under Google's
structured-data policy is "markup inconsistent with visible content", a category that can
draw a manual action, not just a ranking discount.

Update time matters especially for GEO: AI answering questions clearly prefers recent
content, above all for policy, rates, and process — the things that change. A 2023 insurance
guide, however correct, hardly gets cited.

## How to deliver

One line at the top of the page doc; change it only on **substantive content updates**:

```yaml
date_published: 2026-03-12
date_modified: 2026-08-25
```

What counts as "substantive":

| Change | Counts | Why |
|---|---|---|
| a new section added | ✓ | the reader gets something new |
| rate / policy numbers updated | ✓ | the conclusion changed |
| process steps changed | ✓ | same |
| a typo fixed | ✗ | what the reader gets is unchanged |
| an image swapped | ✗ | same |
| layout adjusted | ✗ | same |

## Common mistakes

- **Using it to fake freshness** — bumping the date forward weekly with the content untouched. Google compares against actual content changes; getting caught is a negative signal, and it destroys the field's own credibility — when you truly update later, nobody believes it
- **Body changed, date forgotten** — even more common than the last one; the content is new yet looks stale
- **The two outlets written separately** — a hand-typed "Updated ..." on the page, JSON-LD pulling `updated_at` from the database. The database value moves on a typo fix; the page value relies on memory — they will diverge sooner or later. **The fix: render one field twice.** That's a frontend implementation requirement; you only have to guarantee one delivered value
- **Publish and modified dates set to the same day and never changed** — as good as not having the field
