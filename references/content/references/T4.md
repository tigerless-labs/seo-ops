# T4 · `ymyl` 判定(每页)

> 下游:[C21 YMYL 信任块](../../checklist/references/C21.md) — 这是条件项的**唯一开关**。

## 介绍

`ymyl` 是一个布尔标记,决定这一页要不要做那一整套信任块([T12](T12.md)):
作者实名与资质、审核人与审核日期、官方来源引用。

**漏标比标错危险。** 标了 `true` 而做不到,C21 人审会红,有人来问;
漏标 `false`,C21 整条**不触发** —— 报告上不是红,是「不适用」,于是没人管。
**没测 ≠ 没事**,但看报告的人很容易把它们当成一回事。

> **2026-08-25:本条原为「页型 + ymyl」,页型部分已退役。**
> 页型曾用来开关条件检查,但 Google 不消费 `WebPage` 子类型(`ItemPage`/`CollectionPage`/
> `AboutPage` 等),而维护页型声明要 content 逐页判断、漏标即静默失效 ——
> 一条要人天天喂、下游又没有消费方的输入,不值得留。条件项改由 flag 与内容条件触发。

## 怎么交

页面 doc 顶部一行:

```yaml
ymyl: true
```

判据:**这页的内容会不会影响读者的健康、财务、法律处境或人身安全。**

| 页 | ymyl | 为什么 |
|---|---|---|
| 保险产品页 | ✓ | 买错了直接影响财务与就医 |
| 理赔流程指南 | ✓ | 操作错了拿不到钱 |
| 身份转换期保险衔接 | ✓ | 涉及法律身份 + 财务 |
| 公司介绍 / 团队页 | — | 读错了没有实质损失 |
| 品牌故事 | — | 同上 |

**拿不准就标 `true`。** 代价不对称:误标 `true` 多做一份信任块;
误标 `false` 是 YMYL 内容裸奔上线,这是 R2 红线。

## 常见错误

- **只按「是不是医疗」判** —— 财务、法律、人身安全同样算;保险几乎全线踩中
- **改版时忘了改** —— 一个品牌故事页后来加进了理赔操作步骤,`ymyl` 没跟着变
- **交了 `false` 但页面上挂着作者与审核署名** —— 那说明它实际是 YMYL 内容,
  标记和内容对不上;C21 不触发,署名也就没人核实真伪(比不写署名更糟)
- **整站一刀切标 `true`** —— 看似安全,实际是把 T12 变成每页都要交的必交项,
  content 交不动就会开始编;**编出来的审核署名是 R2 红线**,比漏标严重
