# T8 · 语言配置与双语成对(每页)

> 下游:[C22 hreflang](../../checklist/references/C22.md) — 人审项(双向互指 + x-default)。

## 介绍

`hreflang` 告诉引擎「这一页还有别的语言版本,在这些 URL」。它的判定有个反直觉的性质:

**必须双向互指,一边缺了整对失效。**

中文页声明「我的英文版在 /guide/x」,英文页也必须声明「我的中文版在 /zh/guide/x」。
只有单边声明,引擎会忽略整组关系 —— 不是打折,是当没有。

后果是两个语言版本被当成**互相重复的内容**,引擎挑一个收录、另一个降权。
辛苦翻译的那一版可能根本进不去索引。

## 怎么交

页面 doc 顶部:

```yaml
locales: [en, zh]                # 本页存在的语言版本
default_locale: en               # 语言不匹配时的兜底(→ x-default)
```

单语页**显式声明**,不要留空:

```yaml
locales: [en]
locale_note: en only            # 明确:这页只做英文,不是中文版还没交
```

这一行的价值在于:**「只做英文」和「中文版还没交」在数据上长得一模一样**,
不写清楚,没人知道该不该去催。

**双语页 en/zh 同交,不留单边。** 如果中文版要晚两周上,那这两周 hreflang 是坏的
—— 要么两版一起上,要么先按单语页声明,中文版好了再一起改成双语。

## 常见错误

- **中文版晚上线** —— 最常见。中间那段时间不是「还没做完」,是**线上有个坏掉的声明**
- **只翻正文,没翻 title/description** —— 中文页挂着英文 title,搜索结果里读者不点
- **两个语言版本内容不对应** —— hreflang 声明的是「同一内容的不同语言」;
  中文版顺手删了两节,就不再是对应关系了
- **用地区码当语言码** —— `hreflang="cn"` 是错的(`cn` 是国家码);中文简体是 `zh-Hans` 或 `zh-CN`
- **忘了 x-default** —— 没有兜底时,语言不在列表里的读者会被随机分配
