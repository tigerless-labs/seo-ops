# T1 · canonical brand-name spelling + official social account list (site-level)

> Downstream: [C12 JSON-LD complete and valid](../../checklist/references/C12.md) — under-supplied means the Organization `name` / `sameAs` have no source, C12 goes red.

## Introduction

Search engines and AI don't recognize a "company", only an **entity**. Two things convince
them "these three sites are the same company": one canonical name, and one set of links
pointing at the same official accounts (`sameAs`).

Inconsistent spellings — Tigerless / TigerLess / Taigelesi — may be read as three different
entities, each accruing its own authority, none of them ever growing. `sameAs` exists to
**merge brand traces scattered everywhere into one**: the LinkedIn page, the X account, the
wiki entry, the Crunchbase profile corroborate each other, and only then does the entity stand.

Deliver once; change only when it changes (rename, new account, account retired).

## How to deliver

One table, in the site-level config (not per page doc):

| Field | Content | Notes |
|---|---|---|
| Legal name | Tigerless Insurance Services, Inc. | matches the business license / registration papers |
| Display name | Tigerless | used on pages and in titles |
| Chinese name | Taigelesi | for Chinese pages; write "none" if there isn't one — don't invent one on the spot |
| Short name / alias | TGL | write it if it exists, otherwise leave blank |
| logo | full URL | **>=112×112 px, PNG/JPG (not SVG)**, square or near-square, opaque background |
| Official accounts | one **full URL** per line | see below |

List official accounts as full URLs, not handles:

```
https://www.linkedin.com/company/tigerless
https://x.com/tigerless
https://www.youtube.com/@tigerless
https://www.crunchbase.com/organization/tigerless
```

## Common mistakes

- **Handles instead of URLs** — `@tigerless` points at different things on different platforms; machines can't resolve it
- **Employee personal accounts mixed in** — `sameAs` declares "this is also the company"; personal accounts aren't, and mixing them in pollutes the entity graph
- **A LinkedIn personal page as the company page** — `/in/xxx` is a person; `/company/xxx` is the company
- **Retired accounts never removed** — a `sameAs` pointing at a 404 is a negative signal, not a neutral one
- **Logo delivered as SVG** — Google's Organization logo explicitly rejects SVG; delivering one is the same as delivering nothing
- **The three sites each delivering their own copy** — this item is **company-level**, one copy shared by all three sites; separate copies undo the entity merge entirely
