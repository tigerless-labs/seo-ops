# T7 · H2/H3 大纲(每页)

> 下游:[C17 标题层级](../../checklist/references/C17.md)(层级不跳级)+ **C7/C12 的内容形状要求**(GEO 内容形状)。

## 介绍

大纲同时服务两件事:

1. **机器读的目录树** —— h1 → h2 → h3 逐级不跳。这是 C17 判的。
2. **AI 能不能摘走单独一节** —— 这是 GEO 的核心。

第二件事值得展开:**AI 引用的是段落,不是整页。** ChatGPT 回答一个问题时,
抓的是某一节的开头几句,而不是把你整篇文章塞进答案。所以一节能不能被摘走,
取决于它**离开上下文还成不成立**:

- 小节标题是不是读者真会问的那句话
- 第一段是不是直接给结论,还是先铺垫三句

「先铺垫再给结论」是人类写作的习惯,但对 AI 摘取是致命的 —— 它摘到的是铺垫。

## 怎么交

大纲**在页面 doc 顶部的 SEO 头部块里结构化交**(与 title/h1 同一块,不写进正文段落),
交层级结构 + 每节第一句话的意思:

```yaml
h1: F1 学生签证期间,医疗保险该怎么选

outline:
  - h2: F1 学生必须买医疗保险吗?
    lead: 大多数学校强制要求,且必须满足 waiver 条款;不是联邦法律强制,是学校规定。
  - h2: 学校的 waiver 要求一般看哪几项?
    lead: 四项——年度上限、自付额、遣返/送返条款、承保期覆盖整个学期。
    h3:
      - title: 自付额(deductible)怎么算合格
        lead: 多数学校要求 ≤$500……
  - h2: 什么时候可以用校外保险替代校方计划?
    lead: 满足全部 waiver 条款且在 waiver 截止日前提交证明。
```

`lead` 是**这一节的结论一句话**,不是段落成品文案 —— 正文写作时把它展开成第一段。

**为什么单独成块、不混进正文**:大纲是被逐条查的输入(C17 判层级,C7/C12 判内容形状),
混在正文里就得有人从文章中间去找;单独一块,写的人一眼看得全层级有没有跳级,
查的人也不用读完全文。同理适用于头部块里的所有字段 —— 唯一的例外是图片 alt([T14](T14.md)),
它必须贴着图走。

要点:

- **h2 下面才能是 h3**,不能从 h2 直接跳 h4,也不能 h1 直接到 h3
- **指南 / FAQ 类内容:h2 用用户的问法原句**。「F1 学生必须买医疗保险吗?」
  比「保险要求概述」好——前者是有人真的会打进搜索框的话
- **每节第一段就是结论**,论证放后面
- FAQ 按独立问答块写(供 FAQPage JSON-LD 取值,见 [C12](../../checklist/references/C12.md))

## 常见错误

- **跳级** —— 最常见的原因是视觉理由:「h2 显示太大了,用 h3 吧」。
  **层级是语义,字号是样式**;想小一点让 UI 改 CSS,不要改标签
- **h2 写成营销标语** —— 「全方位的守护」,既不是问题也不是主题,AI 摘走也没用
- **结论放段末** —— 整节读完才知道答案;AI 只摘前面,摘到的是铺垫
- **一节里塞三个问题** —— 摘走的那一段回答不完,AI 会跳过去找别人的页
- **只交大纲不交首段结论** —— 那 frontend 拼出来的还是一堆空标题
