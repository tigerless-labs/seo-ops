# T3 · URL(每页)

> 下游:**无 checker 条目** —— 这条靠评审,不靠脚本。原因见下。

## 介绍

URL 是页面**唯一不可逆**的交付物。

正文写错了改就是了,title 长了改一行,JSON-LD 缺字段补上去。URL 一旦上线就被外链引用、被
收藏、被搜索引擎索引;要改就得挂 301,而 301 会折损一部分权重、让旧外链多绕一跳,
社交平台上已经分享出去的卡片可能直接失效。

**所以这条的成本结构是反的:评审一次很便宜,返工很贵。** checker 也故意不判它 ——
判了也改不动,只会在报告上堆一堆改不了的红项。**约束要放在能起作用的时点上**,
对 URL 而言那个时点是上线前的评审,不是上线后的扫描。

## 怎么交

每页 doc 顶部写清建议路径。规则:

| 规则 | 好 | 坏 |
|---|---|---|
| 全小写 | `/guide/f1-to-h1b` | `/Guide/F1-to-H1B` |
| 连字符分词 | `/pet-insurance` | `/pet_insurance`、`/petinsurance` |
| 层级反映品类 | `/sort/f1`、`/guide/claim-process` | `/page23`、`/p/a1b2` |
| 用读者的词 | `/dental` | `/oral-health-product-line-b` |
| 不含日期 | `/guide/tax-filing` | `/2024/03/tax-filing`(除非是新闻/活动) |
| 不含文件后缀 | `/aboutus` | `/aboutus.html` |
| 非 ASCII 百分号编码 | `/zh/保险指南` 落地成 `%E4%BF%9D%E9%99%A9...` | 直接混排未编码字符 |

新增 URL 过评审 —— 不是走流程走形式,是因为**这是唯一一次改的机会**。

## 常见错误

- **用内部黑话** —— `/sort/f1` 里的 `sort` 是内部叫法,读者不认识;新路径别再引入这类词
- **关键词堆砌** —— `/best-cheap-f1-student-health-insurance-usa-2026`,又长又像垃圾站
- **拼音混英文** —— `/baoxian-guide`,中英文读者都不认
- **层级为了 SEO 而深** —— `/insurance/health/student/f1/plan`,五层没有信息增益,只是难记
- **上线后改** —— 真要改就配 301 并同步:sitemap、内链、llms.txt(T2)、已发出去的分享链接
