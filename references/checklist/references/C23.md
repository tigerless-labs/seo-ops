# C23 · 收录页无 noindex(P0)

## 介绍

`noindex` 是**从索引里删页**的指令,不是「排名打折」——引擎读到就把页面整个移出结果。
误留一个 noindex,页面查无此人,而**其余检查全绿**:canonical 对、JSON-LD 齐、CWV 达标,
只是没人看得到。这是最安静的事故,所以是 P0。

**为什么不并进 C16。** C16 读的是同一个 `<meta name="robots">` 标签,只取
`max-snippet` / `max-image-preview` 两个指令。同标签、同一次抓取,看似该合并——
但**优先级不同**:C16 红 = 摘要展示打折(P1),C23 红 = 页面消失(P0)。
合并后一行只能挂一个优先级,triage 时分不清「急救」还是「排期」,
`checks` 表也无法按优先级过滤。**优先级不同即不合并**,这是编号纪律的分界线。

## 判定的自证性

样本来自 sitemap。**进 sitemap = 站点自己声明「这页要收录」**,同一页再挂 noindex
就是自相矛盾——**零外部输入**、不需要人判断,checker 直接判红。
这与 C12「出现即查」、C19「自称文章即查 og:type」是同一条原则:
**让页面自己的声明互相验证**,零依赖外部配置。

## 实现指导

- 两条通道都要看,漏一条等于没查:

```html
<!-- 通道一:HTML meta(注意 googlebot 是独立的一条,不被 robots 覆盖) -->
<meta name="robots" content="noindex">
<meta name="googlebot" content="noindex">
```

```
# 通道二:HTTP 响应头(非 HTML 资源只能走这条,也最容易被 CDN 规则误伤全站)
X-Robots-Tag: noindex
```

- `none` 等价于 `noindex, nofollow`,同样判红
- **典型事故源**:预发环境模板带 `noindex` 防收录,上线时没摘;
  或 CDN/反代给整个路径段加了 `X-Robots-Tag`,只为挡某个子路径,结果误伤同段的收录页
- 收录页的 robots meta 只该出现授权类指令(C16),不该出现禁止类;
  两类混在同一个 `content` 里更危险——`max-snippet:-1, noindex` 这种写法,授权部分毫无意义
- 真正不该收录的页(登录态、后台、纯业务页)本就不该进 sitemap;
  **判定不冲突的前提是这两个集合互斥**
- 自查:抓页 grep robots/googlebot meta + `curl -I` 看 `X-Robots-Tag`;
  上线后用 GSC「网址检查」确认索引状态
