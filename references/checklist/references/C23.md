# C23 · no noindex on indexed pages (P0)

## Introduction

`noindex` is the directive that **deletes a page from the index**, not a "ranking discount" — the moment the engine reads it, the whole page is moved out of results.
One stray noindex and the page is nowhere to be found, while **every other check stays green**: canonical right, JSON-LD complete, CWV passing —
just nobody can see it. It is the quietest kind of incident, hence P0.

**Why not merge into C16.** C16 reads the same `<meta name="robots">` tag, taking only the
`max-snippet` / `max-image-preview` directives. Same tag, same fetch, so merging looks right —
but the **priorities differ**: C16 red = snippet display discounted (P1), C23 red = page gone (P0).
A merged row could carry only one priority; triage could not tell "emergency" from "schedule it",
and the `checks` table could not filter by priority. **Different priorities means no merging** — that is the dividing line of the numbering discipline.

## Why the verdict is self-evidencing

Samples come from the sitemap. **Being in the sitemap = the site's own declaration that "this page should be indexed"**; hanging a noindex on the same page
is self-contradiction — **zero external input**, no human judgment needed, the checker goes straight to red.
This is the same principle as C12's "check whatever appears" and C19's "claims to be an article, so check og:type":
**let the page's own declarations validate each other**, zero dependence on external configuration.

## Implementation guidance

- Both channels must be inspected; missing one equals not checking:

```html
<!-- Channel 1: HTML meta (note googlebot is its own separate line, not covered by robots) -->
<meta name="robots" content="noindex">
<meta name="googlebot" content="noindex">
```

```
# Channel 2: HTTP response header (non-HTML resources have only this channel; it is also the easiest for a CDN rule to hit the whole site by mistake)
X-Robots-Tag: noindex
```

- `none` is equivalent to `noindex, nofollow`, judged red the same way
- **Classic incident sources**: the staging template carries `noindex` to keep staging out of the index and nobody removes it at launch;
  or the CDN/reverse proxy adds `X-Robots-Tag` to a whole path segment just to block one sub-path, hitting the indexed pages in the same segment
- The robots meta on indexed pages should carry authorization-class directives only (C16), never prohibition-class ones;
  mixing the two classes in the same `content` is even more dangerous — in `max-snippet:-1, noindex` the authorization part is meaningless
- Pages that genuinely should not be indexed (logged-in, admin, pure business pages) should never be in the sitemap in the first place;
  **the two verdicts stay conflict-free only because these two sets are mutually exclusive**
- Self-check: fetch the page and grep the robots/googlebot metas + `curl -I` for `X-Robots-Tag`;
  after launch confirm index status with GSC URL Inspection
