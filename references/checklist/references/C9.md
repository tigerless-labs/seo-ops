# C9 · server-side full body (P0)

## Introduction

Most AI crawlers and some search crawlers **don't execute JS**: a CSR shell page might as well not exist for them. The body must be in the server-rendered HTML; JS only enhances.
Verdict: body length fetched with JS disabled >= 90% of the browser-rendered version.

## Implementation guidance

- Indexed pages render the body on the server (SSG/SSR both fine, see C15); interactive enhancement (Vue/React client logic) does not carry the body
- Next.js (App Router), four disciplines (source: apsu delivery Supplement section 1.2, field-proven):
  - Content pages fetch data in **Server Components**, don't move it client-side
  - Never `"use client"` a whole page/layout -- push interactivity down into leaf components
  - Lazy-loading content blocks (carousels, animated sections) must not add `ssr: false`
  - Content pages must not call `cookies()` / `headers()` (that opts out of static generation, going per-request)
- Collapsed areas (FAQ accordions, tabs) must also have their content in the HTML; interaction only toggles visibility
- Self-check:

```bash
# visible text volume fetched without JS, compared against the browser-rendered version (>=90%)
curl -s -A "<real browser UA>" <url> | python3 -c "import sys,re;h=sys.stdin.read();t=re.sub(r'<script.*?</script>|<style.*?</style>|<[^>]+>',' ',h,flags=re.S);print(len(' '.join(t.split())))"
```
