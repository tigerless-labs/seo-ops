# C29 · URL hygiene (P2)

## Introduction

Four format rules for canonical addresses, scanned over the sitemap URL list (the sitemap **is** the site's
declared canonical roster, so scanning it needs zero extra fetches):

| Rule | Why |
|---|---|
| **lowercase paths** | URLs are case-sensitive: `/About` and `/about` are two URLs, i.e. instant duplicate content |
| **hyphens, not underscores** | Google treats `-` as a word separator; `_` support is inconsistent across engines — `blue_widgets` may be read as one token |
| **no raw non-ASCII** | Raw CJK/accents in a URL are invalid per the URL spec; they must be percent-encoded. Encoded UTF-8 URLs are fully supported by Google — the sin is the *raw* bytes, which some parsers/sharers mangle |
| **no query params on canonical addresses** | `?page=2&sort=x` breeds unbounded URL variants that split signals and burn crawl budget; canonical entries in the sitemap should be parameter-free paths |

## Verdict method

Regex scan of every sitemap `loc`. Raw non-ASCII = red (spec-invalid); uppercase / underscore / query = red with
counts and an example each. This is deliberately a **new-URL standard enforced at the roster level** — see the
renaming warning below before "fixing" old URLs.

## Implementation guidance

- **Do not mass-rename existing URLs to satisfy this check.** A URL change is a migration: 301 the old address,
  update internal links, accept a temporary ranking wobble, and lose a slice of external-link equity. For an
  existing URL, run the math: high-traffic/high-backlink pages usually aren't worth renaming for hygiene alone —
  enforce the rule on **new** URLs and migrate old ones only when touching them anyway
- Enforce at generation time: slugify functions in the CMS/route layer (lowercase + hyphenate + transliterate or
  percent-encode) so bad URLs can't be minted
- Case-sensitivity backstop: serve a 301 from any wrong-case path to the canonical lowercase one (a rewrite rule),
  so external links with wrong case consolidate instead of duplicating
- Parameters: canonical content lives at parameter-free paths; parameterized views (sort/filter/track) carry a
  canonical to the clean URL (C8) and stay out of the sitemap (C2)

## Authoritative references

- [Google: URL structure best practices](https://developers.google.com/search/docs/crawling-indexing/url-structure) — hyphens over underscores, encode non-ASCII, avoid parameter sprawl; the direct source of all four rules
- [WHATWG URL spec](https://url.spec.whatwg.org/) — why raw non-ASCII is invalid and what encoding is normative
