# C15 · render cost not per-request (P2)

## Introduction

Rendering cost for indexed pages must not be per-request: SSG renders at build time and passes by nature; SSR must rely on CDN caching to compress "compute on every request" into "compute once a day". This is also the main lever for LCP (C4).
The verdict branches on the site's declared rendering strategy; with no strategy declared there is nothing to judge.

## Implementation guidance

- **SSG/ISR routes**: rendered at build time, pass by nature; cache headers not required (adding them speeds up LCP)
- **SSR routes**: response headers (effective at the CDN layer):

```http
# Example (for reference only; directive semantics: MDN / RFC 9111, RFC 5861)
Cache-Control: public, s-maxage=86400, stale-while-revalidate=604800
```

  Semantics: the CDN caches for 1 day (`s-maxage` applies to shared caches only); for 7 days after expiry it serves the stale copy first and regenerates in the background (SWR, invisible to users)
- **Business/logged-in pages**: `Cache-Control: no-store` as before
- Precondition: satisfy C10 (public version) before enabling caching, or caching turns into an incident
- Cloudflare note: HTML is not cached by default; a Cache Rule must explicitly enable "Eligible for cache"
- Self-check: `curl -I` and inspect the response headers; the second request should show `cf-cache-status: HIT` (or your CDN's hit marker)
