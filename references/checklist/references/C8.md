# C8 · 自引用 canonical(P0)

## 介绍

canonical 是页面对引擎声明「我的规范身份是这个 URL」,收拢 query 参数等 301 管不到的重复(C3 管跳转层,本条管 200 层,互为防线)。
指错(指向别页 / 指向变体 host)比不写更糟。

**canonical 有两条声明通道**:HTML 里的 `<link rel=canonical>`,和 HTTP 响应头 `Link: <…>; rel="canonical"`。
两条同时出现且不一致时,引擎按自己的规则挑一个——**你就失去控制权了**。所以本条查两路,不只查 HTML
(2026-08-25 并入 header 通道)。header 通道最常见的来源是 CDN/反代规则或 PDF 一类非 HTML 资源的配置外溢。

canonical **链**(A→B→C)不单独判:自引用这个判据天然免疫——每页都指自己,就不可能连成链。

## 实现指导

- head 模板统一输出,每页一条、绝对 URL:

```html
<!-- 示例(仅供参考;来源:Google canonical 文档) -->
<link rel="canonical" href="https://www.example.com/guide/f1-to-h1b">
```

- host 形式与 C3 选定的归一结果**逐字一致**(www 与否、尾斜杠、https)
- 带参访问(`?utm_…`、`?page=`)输出的 canonical 仍指无参规范 URL
- 分页/筛选页各自指自己的规范形态,不集体指第一页;双语页各指各的(语言关系交给 hreflang,C22)
- 动态框架注意:canonical 由**页面数据**生成,别从请求 URL 反推(反推会把 utm 参数烤进去)
- **HTML 页不要再发 `Link: rel="canonical"` 响应头**——一个身份声明用一条通道就够,两条只会打架:

```
# 反例:CDN 规则把 header canonical 加到了全站,与 HTML 里的不一致
Link: <https://example.com/guide>; rel="canonical"      ← 裸域
<link rel="canonical" href="https://www.example.com/guide">  ← www

# 正解:HTML 页只留 HTML 那一条;header 通道只给 PDF 等无处写标签的资源用
```
