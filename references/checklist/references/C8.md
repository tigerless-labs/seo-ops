# C8 · canonical self-reference (P0)

## Introduction

The canonical is a page declaring to engines "my canonical identity is this URL"; it mops up duplicates that 301s can't reach, like query parameters (C3 covers the redirect layer, this check covers the 200 layer -- mutual lines of defense).
Pointing it wrong (at another page / at a variant host) is worse than not writing it.

**Canonical has two declaration channels**: the `<link rel=canonical>` in HTML, and the HTTP response header `Link: <...>; rel="canonical"`.
When both appear and disagree, engines pick one by their own rules -- **and you've lost control**. So this check inspects both paths, not just HTML
(the header channel was merged in 2026-08-25). The most common source of the header channel is a CDN/reverse-proxy rule, or configuration spillover meant for non-HTML resources like PDFs.

Canonical **chains** (A->B->C) are not judged separately: the self-reference criterion is naturally immune -- if every page points to itself, no chain can form.

## Implementation guidance

- The head template emits it uniformly, one per page, absolute URL:

```html
<!-- example (for reference only; source: Google's canonical docs) -->
<link rel="canonical" href="https://www.example.com/guide/f1-to-h1b">
```

- The host form matches C3's chosen canonicalization result **character for character** (www or not, trailing slash, https)
- Visits with parameters (`?utm_...`, `?page=`) still emit a canonical pointing at the parameter-free canonical URL
- Paginated/filtered pages each point at their own canonical form, never collectively at page one; bilingual pages each point at themselves (the language relationship belongs to hreflang, C22)
- Dynamic-framework caveat: generate the canonical from **page data**, don't derive it from the request URL (deriving bakes utm parameters in)
- **HTML pages must not also send a `Link: rel="canonical"` response header** -- one identity declaration needs one channel; two only fight:

```
# Anti-example: a CDN rule added a header canonical site-wide, inconsistent with the one in HTML
Link: <https://example.com/guide>; rel="canonical"      <- apex
<link rel="canonical" href="https://www.example.com/guide">  <- www

# Correct: HTML pages keep only the HTML one; the header channel is only for resources with nowhere to put a tag, like PDFs
```
