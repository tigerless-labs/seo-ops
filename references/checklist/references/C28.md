# C28 · security response headers (P2)

## Introduction

Five response headers, all set once at the server/CDN layer, all absent by default on most stacks:

| Header | What it prevents |
|---|---|
| `Strict-Transport-Security` (HSTS) | SSL-stripping: forces the browser to https for every future visit |
| `Content-Security-Policy` (CSP) | XSS / injected resources: whitelists what the page may load |
| `X-Content-Type-Options: nosniff` | MIME sniffing: a "text file" being executed as script |
| `X-Frame-Options` (or CSP `frame-ancestors`) | Clickjacking: your page framed invisibly under someone else's buttons |
| `Referrer-Policy` | URL leakage: full paths (with tokens/queries) sent to third-party sites |

**The SEO impact is indirect** — Google does not rank on these headers — which is why this is P2, not higher.
They're in the C set anyway because (a) crawler-facing trust surfaces (browsers' "Not secure" interstitials,
safe-browsing flags) do feed back into clicks and crawl priority, and (b) the fix is a one-time server config
covering the whole site: the cheapest red-to-green conversion in the entire checklist.

## Verdict method

Site-level: these headers come from the server/CDN config, not from page templates, so **the root's response
speaks for the site**. http/local origins record N.A. (HSTS is meaningless without https). `X-Frame-Options` and
CSP `frame-ancestors` are alternatives — either satisfies the frame-protection row.

## Implementation guidance

- One server block covers everything (nginx shown; CDN dashboards have the same knobs):

```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

- **CSP is the one that can break the site** — a too-strict policy silently blocks your own scripts/styles.
  Roll it out via `Content-Security-Policy-Report-Only` first, watch the violation reports, then enforce.
  The other four are safe to add blind
- `includeSubDomains` on HSTS: only after confirming **every** subdomain serves https — it locks them all in
- Vercel/Netlify/Cloudflare set none of these by default; each has a headers config file / dashboard section
