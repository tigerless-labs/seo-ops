# C14 · no page-hiding scripts (P1)

## Introduction

The anti-flicker mechanism of A/B-testing tools sets `<body>` to `opacity:0` until the script initializes — a JS-executing crawler may capture a blank page. The content is in the DOM but visually invisible, so C9's text-based verdict cannot catch it; hence a separate check.

## Implementation guidance

- Known dangerous forms (the checker scans per config `BODY_HIDE_PATTERNS`; the list grows as new tools appear):
  - VWO SmartCode's `hide_element='body'` configuration
  - Google Optimize-style anti-flicker snippets (`.async-hide { opacity: 0 }`)
  - any equivalent of "`body { opacity: 0 }` + JS timeout to restore"
- Fix direction (in priority order):
  1. Move the A/B split **server-side** (edge/middleware buckets by cookie; what renders is the final version, no flicker problem)
  2. Use the tool's **no-flicker mode** (e.g. VWO's SmartCode without the hide configuration)
  3. If anti-flicker is truly needed: hide only the **specific elements** under experiment, never the body/main container
- Put new third-party scripts (A/B, analytics, chat widgets) through technical review before launch — they all sit on the crawler-visible surface
- Self-check: grep the patterns + confirm the post-render above-the-fold screenshot is not blank; when a new hiding mechanism is discovered, report it to this system so it enters the config list
