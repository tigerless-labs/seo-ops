# C24 · viewport meta present (P1)

## Introduction

Google runs **mobile-first indexing**: crawling and evaluation use the mobile Googlebot, and the mobile version of a page is the version that gets indexed.
Without the `viewport` meta, mobile browsers render at desktop width (typically 980px) and scale down; the page is judged not mobile-friendly,
and mobile rankings take a direct hit — and mobile is the vast majority of search traffic.

One line of tag, almost impossible to get wrong, but **once it is missed (a new template, a new landing page, a tool-generated page) the performance collapse is site-wide**.
Minimal cost, sizable consequence, so one line stays dedicated to watching it.

## Boundary: this check inspects only this one tag

Mobile friendliness also includes tap targets ≥48×48px, body font size ≥16px, contrast ≥4.5:1, etc. —
those are the **human-perceivable surface**; per the checklist definition ("the dividing line is machine-readable surface / human-perceivable surface") they are explicitly outside the C set.
They belong to UI design and frontend implementation; the checker does not touch them. **This check judges only the `<meta name="viewport">` machine-readable declaration.**

## Implementation guidance

- Write it once in the base template's `<head>`; every page inherits it:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

- `width=device-width` is a required component of the verdict: it tells the browser to use the device's actual width as the CSS viewport width
- **Do not add `user-scalable=no` or `maximum-scale=1`** — disabling zoom is an accessibility anti-pattern
  and brings zero SEO benefit; Safari already ignores it, leaving only the bad reputation
- `viewport-fit=cover` as needed (notch-screen safe areas); does not affect the verdict
- Self-check: fetch the page and grep viewport; recheck with Chrome DevTools device emulation or PageSpeed Insights' mobile run
