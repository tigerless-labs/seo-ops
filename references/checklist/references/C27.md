# C27 · valid head (P0)

## Introduction

The `<head>` content model allows exactly eight elements: `title` / `meta` / `link` / `script` / `style` /
`base` / `noscript` / `template`. Anything else (`img`, `iframe`, `div`, a stray `svg`…) is invalid there — and
Google's documented behavior is brutal: **on hitting an invalid element it assumes the head has ended and ignores
every tag after it**. One misplaced `<img>` (a tracking pixel is the classic culprit) silently voids the canonical,
robots meta, OG set, and hreflang group that happened to come after it.

That failure shape is why this is P0 while most per-page items are not: the page still renders fine in a browser
(browsers are forgiving; they just move the element into the body), so nothing looks wrong — but on the crawl
surface, C8/C16/C19/C22/C23's tags on that page have stopped existing. Same disease family as C14 (body-hide) and
C9 (CSR shell): **the page looks fine while it is already missing pieces to machines.** Only here the missing
pieces are the metadata layer itself, which is worse.

## Verdict method

Parse the region between `<head>` and `</head>`; strip comments and whole `script`/`style`/`noscript`/`template`
blocks (their **content** may legally contain markup-looking text — JSON, CSS hacks, inline SVG inside a
template); every remaining element outside the eight-tag whitelist is red. No explicit head element = N.A.

## Implementation guidance

- The usual culprits, in observed frequency order: **tracking pixels** (`<img height=1 width=1>` pasted from a
  vendor snippet "into the head" verbatim), **iframes** from tag managers, **inline SVG favicons** (use a
  `<link rel=icon>` instead), and template bugs where a component renders visible HTML before `</head>`
- Vendor snippets that say "paste into the head" often contain a `<noscript><iframe…></iframe></noscript>`
  fallback — the `noscript` wrapper is legal in head **only while it contains head-legal elements**; an iframe
  inside it is exactly the trap. Move the noscript+iframe pair to the top of `<body>` (Google Tag Manager's own
  install doc does this correctly)
- Order matters within the head anyway: put the critical machine-read tags (charset, title, canonical, robots)
  **first**, so even a truncation bug downstream costs the least
- Self-check: `curl -s URL | sed -n '/<head/,/<\/head>/p'` and eyeball for the eight allowed tags; or the
  checker's C27 row
