# C10 · cached HTML non-personalized (P0)

## Introduction

CDN caching means "the first visitor triggers the render, everyone gets the same copy": once personalized content (username, cart, session) gets baked into the HTML and cached, A's information is served to everyone -- scrambled content + a privacy incident, more dangerous than not caching at all.
Verdict: two anonymous fetches of the same URL diff empty (deterministic output).

## Implementation guidance

- The server renders public content only; personalized blocks stay as empty slots that client JS fills via a side-channel API call:

```html
<!-- example (for reference only; the generic "cache + side-channel personalization" pattern) -->
<header>
  <nav>...public navigation, goes into the cache...</nav>
  <div id="user-slot"></div>          <!-- empty in the cached version -->
</header>
<script>
  fetch('/api/me', {credentials:'include'})
    .then(r => r.ok ? r.json() : null)
    .then(u => { if (u) renderUserSlot(u) })   // filled per user only in the browser
</script>
```

- Bake no per-request values into the HTML: session id, CSRF token, render timestamp, A/B bucket
- When a CSRF token is needed, fetch it via cookie / API, never in the cached HTML
- Paired with C15: **public version first, then turn on caching** (reverse the order and it's an incident)
- Self-check: two anonymous fetches diff empty; then fetch the same URL logged in and confirm the response is still the public version (personalization appears in the browser)
