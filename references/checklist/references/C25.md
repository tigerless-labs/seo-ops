# C25 · no mixed content (P2)

## Introduction

An HTTPS page referencing `http://` subresources (images, scripts, styles, iframes) = mixed content.
Browser handling is tiered:

- **Active mixed content** (script / iframe / css / fetch) — **blocked outright, never loaded**.
  If what got blocked is rendering logic or styles, the page a crawler sees may be a broken page or bare HTML
- **Passive mixed content** (img / audio / video) — modern browsers **auto-upgrade to https** by default;
  if the upgrade fails (the host does not support https) it is blocked, leaving a hole where the image was

The direct impact on us: **the page the crawler sees is not the page you think it is**. Same disease family as C14 (body-hide scripts)
and C9 (CSR empty shell) — **the page looks fine in the browser while it is already missing pieces on the crawl surface**.
Only, mixed content's damage is usually local, hence P2.

## Verdict scope

Only **subresource** reference protocols are judged: `src` of `img` / `script` / `iframe` / `video` / `audio` / `source` /
`embed` / `object`, plus `href` of `link` (stylesheets etc.).

**`<a href="http://...">` does not count** — that is a navigational outlink; it fires only when the user clicks, triggers no mixed-content blocking,
and does not affect this page's rendering. Judging it would only produce noise. (Outlink reachability belongs to C6.)

http pages themselves are not judged (nothing to "mix"); recorded N.A.

## Implementation guidance

- Write all in-site resources as **protocol-relative or absolute https**; never hard-code `http://` in templates
- For third-party embeds (analytics, support chat, maps, video), confirm https support before integrating;
  if unsupported, **do not integrate** — sacrificing the whole page's rendering for one https-less third party is a bad trade
- External image URLs pasted into CMS / content submissions are a common source: rewrite the protocol uniformly at ingestion, or transfer them to your own CDN outright
- Backstop (not a fix): `Content-Security-Policy: upgrade-insecure-requests`
  makes the browser auto-upgrade — it can save production, but it **masks the problem**; the checker should still scan the source and judge red
- Self-check: fetch the page and grep `="http://` (excluding `<a`); the browser console's Mixed Content warnings
