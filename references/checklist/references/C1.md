# C1 · robots.txt allows AI crawlers (P0)

## Introduction

If the AI retrieval crawlers (OAI-SearchBot, PerplexityBot, etc.) can't get into the site, on-site GEO drops to zero across the board -- citations and mentions have no way to happen.
The UA list splits into three classes (training / retrieval / user-triggered fetch); the runtime authority is `ai-crawlers.yaml` at the seo repo root. When a new crawler appears, this system updates the yaml (human-reviewed PR) and the site side follows up by regenerating.

## Implementation guidance

**What "template-generated" means**: robots.txt must never be hand-maintained -- the site side writes a small piece of generation code
(a template), **input = `ai-crawlers.yaml`, output = the robots.txt text**, rendered at build time or request time.
List updated -> regenerate and you're in sync; "forgot to edit it" cannot exist. The generation logic itself is tiny:

```
read ai-crawlers.yaml
-> for every UA under the three crawler classes, emit a block:
     User-agent: <UA>
     Allow: /
-> append the generic block (User-agent: * / Allow: /) and the Sitemap: line
```

Expected output (excerpt):

```
User-agent: GPTBot
Allow: /

User-agent: OAI-SearchBot
Allow: /

User-agent: *
Allow: /

Sitemap: https://www.example.com/sitemap.xml
```

Where it lands is your stack's choice (implementation is free, the output is fixed):
- **Next.js**: `app/robots.ts` reads the yaml and returns rules (framework-native support, generated at build time)
- **PHP / static site**: render it in one step in the build or deploy script, commit the artifact
- Any stack: a 10-line script in CI also works -- the point is **one single data source, never hand-edit the output**

Notes:
- Don't use the "Disallow everything, then whitelist" style -- miss one new UA and you've blocked it entirely
- Under `policy: allow`, unlisted UAs are allowed by default (robots.txt's default semantics); the point of the list is **explicit naming + a baseline the checker can verify against**
- Self-check: `curl <root>/robots.txt`, then confirm each UA against the yaml is allowed
