# C5 · IndexNow key file reachable (P1)

## Introduction

IndexNow is a push-based indexing protocol (the Bing family; ChatGPT search runs on Bing's index, making this a GEO indexing accelerator).
The `{key}.txt` at the site root is the proof of domain ownership -- after receiving a push, the engine comes back to fetch it for verification, preventing third parties from flooding URLs in your name.

## Implementation guidance

- Generate a random key (>=8 hex characters is enough) and put it at the site root: `/{key}.txt` -- **the file name and the file content are the same key string**
  (the engine builds the URL from the key in the push request, fetches the file, then compares the content); it stays there permanently. Default location is the site root;
  a custom location uses the `keyLocation` parameter (use sparingly -- putting it in a subdirectory restricts what you can submit)
- **Report the key to seo-ops for registration** (`INDEXNOW_KEYS` in `~/.config/seo-ops/.env`) -- a prerequisite for C5's verdict;
  unregistered, the checker can only record N.A. Don't commit the key into public repos
- A publish/update hook (after the blog API publish succeeds) POSTs the changed URLs:

```json
// example (for reference only; source: the indexnow.org protocol docs)
POST https://api.indexnow.org/indexnow
Content-Type: application/json
{
  "host": "www.example.com",
  "key": "a1b2c3d4e5f6",
  "keyLocation": "https://www.example.com/a1b2c3d4e5f6.txt",
  "urlList": ["https://www.example.com/blog/new-post"]
}
```

- Merge bulk changes into one POST (the protocol caps a single request at 10k entries); a 200/202 response means accepted
- The checker only verifies the key file is reachable; push behavior lives in the hook logs
