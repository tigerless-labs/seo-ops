# C6 · 站内出链无 4xx/5xx:sitemap 之外的目标(P1)

## 介绍

爬一遍站内链接图,**每条站内链接的目标状态码必须 <400**。链接指向非 200 浪费抓取预算,
也削弱 AI 引用时的可信度。

**与 C2 的分工(2026-08-25 收窄)**:

| | 问的是 | 数据来源 |
|---|---|---|
| **C2** | 你**声明要收录**的 URL 可达吗 | sitemap 条目(抽查) |
| **C6** | 页面上**真实存在的链接**可达吗 | 爬取内链图 |

两者在 sitemap 内的 URL 上重合,所以**本条只报目标不在 sitemap 里的死链** ——
hub 里残留的旧链接、写错的 href、下架后没清的入链。这类 C2 结构上看不到:
它只认 sitemap 那份名单,而这些 URL 压根不在名单上。

**坏出链按修法分两组报,不统称「死链」**(2026-08-25 修正):

| 组 | 含义 | 动作 |
|---|---|---|
| **站内死链**(404 / 410 / 5xx) | 内容没了 | 清入链 —— 下架事务漏了一步(见下) |
| **访问受限**(401 / 403) | 页面存在,只是没给我们内容 | 先确认成因,再按下节处理 |

分开报是因为**修法完全不同**,统称「死链」会让人去找一个根本不存在的坏页面。
两组都算红:爬虫顺着链接撞墙,抓取预算照样烧。

**站外出链不在 checker 范围**:每轮跑要打第三方站,慢且易被 429/403 误报;
站外链接的可达性与权威性归**生成侧自检 + 人审**(blog 发布前查一次,比每日全站扫一遍划算)。

**覆盖不全时记 N.A.,不记 pass。** 被限流或爬取触 `CRAWL_MAX_PAGES` 上限时,
没找到死链只说明「没看完」。已找到的死链照报红 —— 那是确凿的,只是可能还有没爬到的。

## orphan 判定已移除(2026-08-25)

本条一度还查 **orphan**(sitemap 里有、站内却无任何链接指向的页面),判定是
`sitemap 全集 ⊆ 内链可达图`。移除的理由:**它靠「没看见」下结论,而爬不全是常态** ——
限流、`CRAWL_MAX_PAGES` 触顶、登录态区域、语言分簇,任何一个都会让一批页没被看见。

实测:tigerless.com 报 **138 条 orphan**,追下去根因是 C26 —— 按 `Accept-Language` 分流的
302 把不发该头的爬虫锁进 `/cn` 簇,英文那 136 页在自己的语言簇里内链完好,只是从入口不可达。
**真问题是 C26,而 C6 把它翻译成了一个指向错误方向的数字**:读报告的人会去补内链,
而补内链治不好语言分流。

死链判定相反:**「看见了」才报**,抓多少算多少,覆盖不全只影响完整性、不影响已报项的真伪。

内链覆盖仍然重要(无入链的页引擎认为不重要,内链是权重流动的管道),但那是**信息架构**
决策,不该由一个可能没爬全的爬虫下红判。做法留在实现指导里备查。

## 实现指导

- **死链的根因通常是下架流程漏了一步**:页面走了 410,但 hub 列表 / 相关推荐 / 正文里的旧链接没清。
  下架必须是一个事务:移出 sitemap(C2)+ 设 301/410(C13)+ **清入链**——三件事漏一件就在本条红
- 正文内链尽量走**数据引用**(引 slug 由路由表解析)而非手写死 URL,改路径时自动跟着走
- 内链落在**服务端 HTML**里(受 C9 约束)——纯 JS 渲染的链接对不执行 JS 的爬虫不算数
- 自查:从首页爬内链图(或 Screaming Frog 一类工具)看状态码列;
  checker 同判定(config `CRAWL_MAX_PAGES` 限深;触顶或被限流时记 N.A. 不猜)

**内链覆盖(本条不判红,人看)**:每个进 sitemap 的 URL 最好有一条站内可点击链接指向 ——
**hub 页列表**(品类/主题 hub 罗列子页,pSEO 页集的标准做法)、**面包屑**(配 BreadcrumbList,
见 C12.md)、**相关推荐块**三选一可叠加;新页模板自动挂上级 hub 的内链块,不靠人记。

### 访问受限页(401/403)的正确处理

**先定成因**,checker 分辨不了,四种可能:登录态门 / WAF 反爬挑战 / 地域限制 / 权限配错。
看 body 就能分——Cloudflare 挑战页写着「Just a moment...」(2026-08-25 tigerless.com 的
`/login`、`/user/Plan` 三条 403 即此,**不是登录门**)。

**若确为私有区域**(登录后才看的页),三层一起做,缺一层就还会红或还在烧预算:

| 层 | 做什么 | 为什么 |
|---|---|---|
| **入链层** | 未登录用户的服务端 HTML 里**不输出**这些链接;做不到则 `rel="nofollow"` | 最上游。爬虫没见过这条边,后面两层都省了 —— **本条 C6 判的就是这一层** |
| **robots 层** | `robots.txt` 里 `Disallow: /user/`、`Disallow: /account/` | 从源头不抓,省抓取预算 |
| **sitemap 层** | 不进 sitemap | sitemap 的语义是「请收录这些」,私有页进去是自相矛盾(也会触发 C2/C23) |

注意 **`Disallow` 与 `noindex` 不能叠加**:被 `Disallow` 的页爬虫压根不抓,自然读不到里面的
`noindex`,该页仍可能因外链被收录(只是没有摘要)。私有区域通常 `Disallow` 就够——
没人会从站外链到 `/user/Plan`。真需要「已被收录、要它消失」时,反过来:**放开抓取 + `noindex`**(C23)。

**登录页本身是公开页**,应当 `200` 而不是 401/403 ——用户搜「品牌名 登录」是真实需求,
爬虫看得见很正常;不想它占搜索结果就配 `noindex`(C23),而不是拿状态码挡。

**若是 WAF 挑战**:这不是页面配置问题,checker 被拦不代表爬虫被拦。
去 CDN 后台确认规则放行**已验证爬虫**(Cloudflare 的 verified bots 走反向 DNS 校验,
和伪装 UA 不是一回事)。确认放行后本条自然消。
