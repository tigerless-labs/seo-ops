# C2 · sitemap 可达且可信(P0)

## 介绍

sitemap 是收录的主通道:不可达、lastmod 造假、塞着 4xx/5xx 条目,都会让引擎降低对它的信任,收录效率下降。
分片按内容组(core / blog / pseo)统一 index 入口,GSC 才能按组报收录率——这是 pSEO「首批收录率不达标停扩」决策的数据前提。

## 实现指导

- 从数据源**派生**(路由表 / 内容表),禁手维护静态文件;Next.js 用 `app/sitemap.ts`,其他栈构建脚本生成
- `lastmod` 取**真实内容更新时间**(数据行的 updated_at),不许全站同一天、不许取构建时间
- **单份 sitemap 硬上限:5 万条 URL / 50MB 未压缩**(协议规定,非建议值)——**越界整份失效**,
  不是只丢超出的部分。超限或按内容组分片,index 统一入口、静态引用分片名(不随批次变)
  (2026-08-25 并入 checker 判定:逐份计条目数):

```xml
<!-- 示例(仅供参考;格式来源:sitemaps.org 协议) -->
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap><loc>https://www.example.com/sitemap-core.xml</loc></sitemap>
  <sitemap><loc>https://www.example.com/sitemap-blog.xml</loc></sitemap>
  <sitemap><loc>https://www.example.com/sitemap-pseo.xml</loc></sitemap>
</sitemapindex>
```

```xml
<!-- 分片内条目示例(仅供参考;来源:sitemaps.org) -->
<url>
  <loc>https://www.example.com/guide/f1-to-h1b</loc>
  <lastmod>2026-08-20</lastmod>
</url>
```

- **条目自身必须直接返回 200**:sitemap 的语义是「这些就是规范地址」,列一个会 301/302 走的 URL,
  等于交给 Google 一张写错地址的清单。抽查时**必须禁重定向**——跟随了就只看终点,
  `302 → 200` 会被误判为可达(2026-08-25 修:`allow_redirects=False`)
- 下架页同步移出 sitemap(与 301/410 同一事务,见 C13)
- 自查:fetch index 与每个分片 200;禁重定向抽查条目状态码;比对 lastmod 与数据行

## lastmod 三判(2026-08-25 补;旧实现只量「最好的那一条」)

| 判什么 | 旧实现漏在哪 |
|---|---|
| **覆盖率** = 带 lastmod 条目 / 总条目,应为 1.0 | 「有没有」只要一条带就成立,271 条里 1 条也算有 |
| **新鲜度** = 最新 lastmod 距今 ≤30 天 | ✅ 原有;但只看 `max()`,270 条烂在 2021 年也看不出来 |
| **真实性** = 最大单日簇占比 + 该日是否 = 运行当天 | 完全没有;取构建时间的站**永远等于今天,反而永远绿灯** |

真实性这条不需要跨天比对,时间自己就是鉴别器:
**构建时间戳的定义就是「永远等于最近一次构建」**,而 checker 每天跑 ——
它天天命中;真实的批量编辑只在发生当天误报一次,次日日期退到过去自动转绿。
**误报有自愈期,漏报没有**,对每日检查来说这个不对称正是要的方向。

一个更硬的判据备着(眼下不生效):sitemap 的 lastmod 与页面自己的 JSON-LD `dateModified` 打架
→ 必有一方说谎。这是 C12/C19/C23 那条**自证触发**的又一次应用,但只对已有 JSON-LD 的页有效。

> lastmod 的权重是**挣来的**:站点长期诚实,Google 才当真;发现你撒谎,
> 会把整份 sitemap 的 lastmod 一起降权。**假 lastmod 比没有 lastmod 更糟**——
> 没有只是信号缺失,假的是把整个通道的信誉烧掉。取值必须是内容行的 `updated_at`,
> 绝不能是构建时间:那等于每次部署都告诉 Google「全站都变了」,喊几次就没人听了。
