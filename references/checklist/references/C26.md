# C26 · no Accept-Language redirects (P0)

## Introduction

Auto-jumping users to a "guessed language version" based on the browser's `Accept-Language` (or IP geolocation) is an anti-pattern Google's
[localized versions guide](https://developers.google.com/search/docs/specialty/international/localized-versions)
calls out by name. The reason is direct:

**Googlebot crawls with "no language preference" — it sends no `Accept-Language`.**
So it lands on the default branch every time. The other language version is not ranking poorly — it **does not exist to the crawler**:
requesting that URL gets 302'd away, and the crawler never obtains its content. An entire language version's pages stay out of the index — this is the **existence layer**, hence P0.

The same mechanism also contaminates two other verdicts: the landing URL varies with the request headers → C3's four-variant canonicalization drifts;
the auto-jump is usually two hops and up → C20's hop ≤1 goes red. **The root cause is here; those two are only symptoms.**

## Why the verdict is self-evidencing

Same URL, sent twice (`en-US` / `zh-CN`), compare the final landing URLs. A mismatch = a language-based auto-jump exists.
**Zero external input**, no need to know which languages the site supports, monolingual sites pass by nature — the same principle as C12's "check whatever appears",
C19's "claims to be an article, so check og:type", and C23's "in the sitemap means no noindex":
**let the page's own behavior validate itself, zero external configuration dependence.**

## Implementation guidance

- **The correct fix: every language version gets its own stable URL, and none of them auto-jumps.**
  Declare the language relationship with `hreflang` (C22) so engines know they are different versions of the same content
- To serve user experience, use **non-redirect** means: an in-page top banner "This article has a Chinese version →" and let users click for themselves;
  remembering the choice in a cookie is fine too — but **the default path (no cookie, no language header) must serve that URL's own content directly**
- The root path `/` acting as a language chooser or jumping to the default language is acceptable (with `x-default` hreflang);
  but **concrete content pages must not jump**
- Dismantling an auto-jump already in production: first give each language version its own URL and guarantee a direct 200,
  then complete the hreflang, and only then remove the jump logic — in the reverse order both versions briefly 404

```
# Anti-pattern (measured on tigerless.com /home, 2026-08-25)
Accept-Language: en-US   →  302 → 200  https://www.tigerless.com/          English
Accept-Language: zh-CN   →  302 → 302 → 200  https://www.tigerless.com/cn  Chinese
(no Accept-Language)     →  302 → 302 → 200  https://www.tigerless.com/cn  ← what the crawler sees
```

- Self-check: `curl -sI -H 'Accept-Language: en-US' <url>` once and again with `zh-CN`; compare `Location`;
  the checker judges the same way (config `LANG_REDIRECT_PROBES` / `LANG_REDIRECT_SAMPLE_SIZE`)
- The checker itself **deliberately sends no `Accept-Language` and stores no cookies**, to align with the crawler's viewpoint;
  when touching the Fetcher, do not lose this posture
