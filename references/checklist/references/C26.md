# C26 · 不按 Accept-Language 分流(P0)

## 介绍

按浏览器 `Accept-Language`(或 IP 地理)自动把用户跳到「猜测的语言版本」,是 Google
[多语言版本指南](https://developers.google.com/search/docs/specialty/international/localized-versions)
明确点名的反模式。原因很直接:

**Googlebot 按「无语言偏好」抓取 —— 它不发 `Accept-Language`。**
所以它每次都落到默认分支。另一个语言版本不是排名差,是**对爬虫不存在**:
请求那个 URL 会被 302 走,爬虫永远拿不到它的内容。整整一个语言版的页面收不进索引 —— 这是**存在层**,故 P0。

同一个机制还会连带污染两处判定:落点随请求头变 → C3 的四变体归一飘;
自动跳转通常是两跳起 → C20 的 hop ≤1 红。**根因在这里,那两处只是症状。**

## 判定的自证性

同一个 URL,发两次(`en-US` / `zh-CN`),比对最终落点。不一致 = 存在按语言的自动跳转。
**零外部输入**、不需要知道站点支持哪些语言、单语站天然通过 —— 与 C12「出现即查」、
C19「自称文章即查 og:type」、C23「进了 sitemap 就不该 noindex」同一条原则:
**让页面自己的行为互相验,零外部配置依赖。**

## 实现指导

- **正解:每个语言版本各有稳定 URL,谁都不自动跳。**
  语言关系用 `hreflang` 声明(C22),让引擎知道它们是同一内容的不同版本
- 想照顾用户体验,用**非跳转**手段:页内顶部提示条「这篇有中文版 →」,让用户自己点;
  记住选择用 cookie 也行 —— 但**默认路径(无 cookie、无语言头)必须直接给出该 URL 本身的内容**
- 根路径 `/` 做语言选择页或跳默认语言可以接受(配 `x-default` hreflang);
  但**具体内容页不能跳**
- 已经上线的自动跳转要拆:先给每个语言版分配独立 URL 并保证直达 200,
  再把 hreflang 补齐,最后才移除跳转逻辑 —— 顺序反了会短暂出现两版都 404

```
# 反例(2026-08-25 实测 tigerless.com /home)
Accept-Language: en-US   →  302 → 200  https://www.tigerless.com/          英文
Accept-Language: zh-CN   →  302 → 302 → 200  https://www.tigerless.com/cn  中文
(不带 Accept-Language)    →  302 → 302 → 200  https://www.tigerless.com/cn  ← 爬虫看到的
```

- 自查:`curl -sI -H 'Accept-Language: en-US' <url>` 与 `zh-CN` 各一次,比对 `Location`;
  checker 同判定(config `LANG_REDIRECT_PROBES` / `LANG_REDIRECT_SAMPLE_SIZE`)
- checker 自身**显式不发 `Accept-Language` 也不存 cookie**,以对齐爬虫视角;
  改动 Fetcher 时别把这个姿态弄丢了
