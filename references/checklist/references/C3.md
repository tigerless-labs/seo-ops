# C3 · URL canonicalization (P0)

## Introduction

Goal: every page has exactly one URL identity. www/apex x http/https x trailing slash can spell the same page as multiple addresses; the fallout of not canonicalizing comes in three layers:

1. **Duplicate crawling** -- engines crawl each variant as a separate page; crawl budget burns on duplicate content, and new pages get crawled slower instead;
2. **Split equity** -- some backlinks point at www, some at the apex; link equity is booked against different variants. A page whose combined equity could rank up front ranks nowhere when it's split;
3. **Downstream loses its baseline** -- C8's canonical, the sitemap's URLs, and hreflang's reciprocal pointers all require writing "the one URL"; without canonicalization there is no "the one".

**Needs a real domain to test** (DNS/certificate layer); on a local deployment the checker records N.A.

## Implementation guidance

- **One place of configuration** at the server / CDN: every variant 301s to the single canonical host; decide three things -- www or apex, force https, trailing-slash convention
- Variants must reach the final form **in one hop** (also constrained by C20); no http->https->www chains:

```nginx
# example (for reference only; nginx syntax, CDN rules work the same way)
server {
    listen 80;  listen 443 ssl;
    server_name tigerless.com;              # apex (including http)
    return 301 https://www.tigerless.com$request_uri;   # one hop straight to the final form
}
```

- Trailing slash: pick one (no trailing slash recommended), 301 the other over; configure at the framework layer (Next `trailingSlash`, nginx `rewrite`)
- Self-check: `curl -I` the four variants (http/https x www/apex); all must 301 with an identical Location and hop=1
